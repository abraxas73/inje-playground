# 관리 규칙 수정 및 Master DB 선택 검증

2026-09-14. 구현·운영 반영 완료.

## 사용하는 방법

### 규칙 추가·수정·복원

1. `/marketing`의 **관리 규칙**에서 목록을 연다 (`/marketing/rules`).
2. 원본 또는 추가 규칙의 **수정**으로 이름·설명·검사 방식·대상 항목·적용 조건·등급·활성을 바꾼다.
3. 변경 사유를 입력하고 **초안 저장** 또는 **저장 및 적용**을 선택한다. 초안은 현재 적용 정책을 바꾸지 않는다.
4. **수정본 시험 검증**은 초안을 저장하고 그 내용을 고정해 Master에 시험한다. 시험 실행으로 표시되며 현재 정책에는 영향이 없다.
5. **이력**에서 이전 적용본과 변경 사유를 조회한다. **이 버전으로 복원 초안**은 현재 버전을 기준으로 새 수정본을 만들며 이전 이력을 덮어쓰지 않는다. 이력은 페이지별로 모두 조회할 수 있다.

변경된 버전을 다른 편집자가 덮어쓰면 저장을 거절한다. 적용에 성공한 요청을 같은 내용으로 다시 보내도 새 버전이 중복 생성되지 않는다. 원본 규칙 16개 모두 수정 버튼을 제공하며, 최초 버전은 보존했다.

**회사명 필수(EXCEL-03)**는 회사 연결의 구조상 이름·설명만 수정할 수 있다. 해당 화면에 이유를 표시한다. 권한·승인 경로·고유 DB ID·이메일 고유 제약·참조 및 감사 이력 보호는 업무 규칙 변경으로 해제하지 않는다. 성명·이메일 필수, 이메일/날짜 형식 등 나머지 업무 기준은 적용 버전에 따라 동작하며 기존 Form·검수 코드의 중복 하드코딩을 제거했다.

### 전체·일부 Master 검사

1. Master의 **규칙 검증**을 누른다. 필요하면 먼저 필터를 적용하거나 개별 행을 체크한다.
2. **전체 Master / 현재 필터 결과 전체 / 직접 선택한 Contact** 중 대상을 고른다.
3. 실행할 규칙을 1개 이상 선택하고 대상 건수를 확인해 실행한다.
4. `/marketing/validations`의 실행 이력과 결과 화면에서 진행률·판정·후속 처리를 확인한다.

체크박스가 있는 첫 열은 화면 전용이며 기존 Excel 18개 데이터 컬럼과 2줄 헤더를 유지한다. 헤더 체크박스는 현재 페이지 25건 선택이고, 필터 결과 전체 검증은 별도 대상 옵션이다. 페이지·정렬 이동은 선택을 보존하며 필터 변경은 선택을 해제하고 알린다.

규칙 관리에서 규칙을 먼저 선택해 **선택 규칙으로 검증**하는 진입점도 제공한다. 일부 Contact만 검사해도 중복 후보는 실행 당시 전체 Master와 비교하며 자기 자신과 빈 비교 키는 제외한다.

### 결과와 후속 검수

- **Contact별 결과**: DB ID·회사·성명·대표 판정·확인 항목·현재 자료 변경 여부·후속 처리.
- **규칙별 집계**: 선택 규칙/판정별 Contact 수와 영향받는 고유 회사 수. 동일 Contact가 여러 규칙에 포함될 수 있음을 표시한다.
- 필터: 규칙, 판정, 규칙 등급, 회사·성명·DB ID, 후속 처리 상태.
- DB ID를 누르면 검사 당시 값·사유·관련 후보·원본 Contact 값·담당자 확인 기록을 본다.
- **확인 기록 저장**: 근거를 적어 확인 완료 또는 보류. 원래 판정은 보존한다.
- **변경 요청 작성**: 최신 Contact를 Form으로 불러와 검토·제출한다. 결과와 제출은 DB 트랜잭션에서 연결하고 기존 검수·승인 후 Master에 반영한다. 실행/Contact별 고정 요청 키로 같은 요청이 중복 생성되지 않는다.
- **결과 Excel 다운로드**: 현재 결과 필터 전체를 `검증 결과`, `실행 정보` 시트로 제공한다. 25건 페이지 제한을 적용하지 않으며 검사값을 수식으로 실행하지 않는다.

판정은 통과·미충족·확인 필요·대상 아님·실행 오류다. 모두 조건 비해당인 자료를 통과로 표시하지 않는다. 담당자 확인이 필요한 기준은 자동 통과하지 않으며 선택하지 않은 규칙까지 검증했다고 표시하지 않는다.

데이터·회사 기준·비교 대상 또는 규칙이 변경되면 당시 결과라는 경고를 표시한다. 확인 완료는 최신 근거로 다시 검증해야 한다. **최신 기준으로 다시 검증**은 새 실행을 만들고, **미처리·오류 재시도**는 같은 고정 자료와 규칙을 이어서 검사한다. 이전 실행 오류 기록도 보존한다.

## 원본 16개 기준의 실행 구분

- 필드 자동 검사 5개: 회사명, 성명, 이메일 필수, 이메일 형식, 최종확인일.
- Master 비교 검사 5개: 중복 후보, 표준 회사 연결, 회사 분류, 회사 관계, 출처 추적.
- 담당자 확인 4개: 실제 관리 대상, 발송 유효성, Eco 확정 정보, 확인된 사실.
- 운영 원칙 2개: 회사·기관 포괄 범위, 이동·퇴사 시 업데이트 절차. 설명은 편집할 수 있지만 그 자체를 자동 실행 대상으로 제시하지 않는다.

따라서 현재 초기 목록 16개 중 실행 가능한 항목은 14개다. AI·발송 이력·외부 Eco 자료를 조회하지 않는다. Form 제출에는 Excel 원본시트명을 강제하지 않고 제출·승인 이력으로 출처를 추적한다.

## 구현 구조와 설계 조정

- 적용 규칙: 기존 `marketing_rules`를 현재 적용본으로 유지해 기존 접수·승인과 호환한다. 불변 적용본은 `marketing_rule_versions`, 수정본은 `marketing_rule_drafts`, 이전 변경 이력은 `marketing_rule_history`에 보존한다.
- 공통 판정: `marketing_evaluate_rule`과 `marketing_validate_rules_context`. 접수·승인·샘플·Master 실행이 같은 필드 검사기를 사용하고, 승인에는 최신 최종값·회사 분류·비교 컨텍스트를 적용한다.
- 실행: `marketing_validation_runs`, `targets`, `reference`, `organizations`, `results`, `followups`. 생성 시 하나의 SQL 문으로 대상·회사·전체 비교 자료를 복사한다.
- 작업 처리: Contact 200건 단위, 실행 행 잠금과 `SKIP LOCKED`, 조각별 결과·진행 상태 원자적 커밋. 모든 처리가 DB 안에서 끝나므로 외부 lease 대신 트랜잭션 잠금을 쓴다. 연결 종료 시 해당 조각만 롤백되며 다음 작업자가 이어받는다.
- 시작 요청 뒤 첫 조각을 처리하고, `pg_cron`의 `marketing-master-validation` 작업이 매분 미완료 작업을 회수한다. 한 번에 약 20초를 작업하고 조각 사이에 커밋한다. 브라우저는 진행 상황만 조회한다.
- 취소는 실행 중 조각의 행 잠금이 끝난 뒤 적용되며 처리한 결과를 유지한다. 시스템 오류는 실패 상태와 오류 코드를 표시하고, 개별 판정 오류는 일부 실행 오류로 구분한다.
- Excel: 서버에서 500 Contact씩 조회해 임시 파일에 스트리밍 작성하고 완성된 파일만 반환한다. 진행·규칙·후속 처리 등의 상태 토큰이나 건수가 페이지 사이에 바뀌면 파일을 반환하지 않는다.
- 접근: 강승억·김하연의 기존 접근 제한을 페이지·API·RLS에 적용한다. 직접 결과/규칙 쓰기와 일반 사용자의 내부 작업자 호출을 차단한다.

주요 API는 `/api/marketing/rules`의 초안/적용 작업, `/rules/{id}/versions`, `/api/marketing/validation-runs`, `/{id}`, `/{id}/followups`, `/{id}/export`다. 설계의 별도 PATCH/publish 경로는 기존 POST API의 명시적 action으로 통합했다.

## 적용 및 검증

적용 SQL: `docs/sql/2026-09-14-marketing-rule-management-v2.sql` (기존 rules·sort 이후 한 번 적용). 초기 v2 적용 환경에는 `docs/sql/2026-09-14-marketing-validation-snapshot-performance.sql`도 적용한다. 새 설치용 본문에는 동일한 최적화를 포함했다.

- 새 로컬 DB에 기존 마이그레이션부터 전체 적용 성공.
- `scripts/check-marketing-rule-management-v2.sql`: 원본 수정, 초안 분리, 버전 보존·낙관적 충돌, 조건부 규칙 선택, 필터 32건 전체, 대상 밖 중복 후보, 실행 요청 중복 방지, 취소/재시도, 이전 실행 오류 보존, 전체 최신 정책 승인, 변경 제출 연결, 접근 및 직접 쓰기 차단.
- 기존 접수·검수·정렬·Excel 및 새 화면·결과 다운로드·접근 테스트 74개 통과, 실제 원본 대조 선택 테스트 1개 생략. TypeScript·ESLint·Next production build 통과.
- 합성 Master 7,294건·회사 2,826개·14개 선택 기준으로 102,116개 결과 생성. 회사 비교 키를 먼저 집계해 대상 스냅샷 생성 시간을 로컬 측정 2.46초에서 0.274초로 줄였다. 로컬 결과 테이블/인덱스 약 46.38 MiB. 운영 성능 보장 수치가 아닌 로컬 측정값이다.
- 결과 조회는 현재 페이지 결과를 한 번에 집계하고 실행별 조건에 맞는 쿼리 계획을 사용한다. 입력은 전부 바인딩하며 사용자 SQL은 실행하지 않는다. 운영 사용자 권한의 500 Contact 조회가 DB 제한 시간 6초 안에 완료됐다.
- 결과 Excel 501 Contact를 페이지 전체에 걸쳐 내보내고 마지막 행·문자열·실행 정보 보존을 검증. 다운로드 중 상태 변화는 409로 거절.

전체 실행의 Contact 대표 판정은 **미충족 1,166건, 확인 필요 6,128건, 실행 오류·미처리 0건**이다. 담당자 확인 규칙을 포함하므로 확인 필요는 데이터 오류 확정을 뜻하지 않는다. 전체 실행은 작업자 대기 시간을 포함해 약 102초에 완료됐다. 자료와 서버 부하에 따라 소요 시간은 달라진다.

운영 검증 전후 Contact 7,294건·회사 2,826개 전체 행의 해시가 동일했다. 원본 출처 7,294건과 제출 0건도 유지됐다. 검증에서 변경 요청 Form을 여는 동작까지 확인했으며 실제 Master 변경이나 검수 제출은 하지 않았다. 미로그인 규칙·실행·상세·다운로드 API는 모두 401을 반환했다.

운영 화면에서 다운로드한 Excel 파일을 직접 읽어 검증했다.

- 필터 실행 파일: Contact 2,149건과 이메일 형식 결과 2,149행 전부 포함.
- 전체 실행 파일: Contact 7,294건마다 정확히 14행, 총 102,116행과 `실행 정보` 시트의 건수 일치. 수식 셀 0개, 실행 오류 0개, 통과 근거 문구 일치.
- 전체 파일의 개별 규칙 판정은 통과 62,824개·미충족 1,898개·확인 필요 30,100개·대상 아님 7,294개다. 앞의 Contact 대표 집계와 집계 단위가 다르다.

AI 연결, Stibee 발송 이력 및 외부 Eco Partner 동기화는 이번 구현에 포함하지 않았다.
