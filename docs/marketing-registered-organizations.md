# 등록된 회사·기관 선택 및 선등록

2026-09-15 변경. Contact 폼의 자유 입력 회사명을 **등록된 회사·기관 검색·선택**으로 전환했다. 신규 회사는 회사·기관 기준에 먼저 등록하고, Contact는 담당자 검수를 거쳐 Master에 반영한다.

## 사용 방법

1. Contact 등록/변경의 **회사명**에서 표준명 또는 승인 별칭을 입력하고 검색 결과를 선택한다. 마우스 클릭 또는 위/아래 화살표와 Enter를 사용할 수 있다.
2. 선택한 표준명·분류·확인 상태를 표시한다. 회사명을 다시 입력하거나 **다른 회사 선택**을 누르면 선택을 해제하며, 새 결과를 선택하기 전에는 제출할 수 없다.
3. 신규 회사는 폼 안 **회사·기관에서 먼저 등록 (새 탭)** → 회사·기관 탭의 **회사·기관 등록**에서 등록한다. 원래 Contact 입력 창은 유지된다. 돌아와 **회사·기관 다시 검색** 후 결과를 선택한다.
4. 회사 등록은 기존 검수 담당자 권한으로 가능하다. 표준명·분류·확인 상태·승인 별칭·등록 근거를 기록한다. 비슷한 표준명/별칭은 중복 등록을 막고, 실제 별도 법인인 경우에만 별도 법인 확인 체크와 판단 근거로 등록할 수 있다. 자동 병합하지 않는다.
5. 이미 회사에 연결된 Master 수정은 해당 회사 ID로 최신 기준을 조회하여 미리 선택한다. 회사 미연결 레코드나 옛 제출은 회사명만으로 임의 확정하지 않고 검색 결과 선택을 요구한다.

## 저장과 검수

- `marketing_submissions.submitted_organization_id`에 제출자가 선택한 회사 ID를 보존한다. `source.companySelection`에는 DB가 읽은 당시 회사·분류·별칭·버전을 기록한다. 원래 제출 데이터는 기존 `submittedData` 등 출처 정보에 보존한다.
- API 및 DB에서 회사 존재·버전을 검사하고 표준명을 적용한다. 존재하지 않는 회사, 오래된 선택, 회사 삭제 요청은 거절한다. 같은 요청 키로 다른 회사 ID를 제출할 수 없다.
- 검수는 제출자가 선택한 회사 ID를 우선 표시한다. 같은 이름이어도 다른 ID로 변경하면 담당자 확인 항목에 변경 근거를 요구한다. 표준 회사명은 직접 편집하지 않고 회사 검색으로 변경한다.
- 검수 화면과 DB 모두 미등록 회사의 즉석 생성·승인을 막는다. 등록된 회사·기관을 선택한 뒤 최종값 재검증을 진행해야 한다. 기존 Excel 수집은 누락/오류 원본도 그대로 접수하고, **승인 시 회사 연결을 필수화**한다. 반려는 회사 선택이나 최종값 검증 없이 사유로 처리할 수 있다.
- 회사 등록은 `marketing_review_events`에 등록자·시각·등록 사유·별도 법인 판단과 등록 내용을 함께 저장한다. 재시도에는 같은 요청 ID를 사용해 중복 등록을 방지하며, 감사 기록 실패 시 회사 등록도 롤백한다. 회사 등록 자체는 Contact/Master를 변경하지 않는다.
- 기존 Master·회사·대기 제출의 값은 일괄 수정하거나 소급 연결하지 않는다. AI·외부 서비스 연계 범위는 변경하지 않는다.

## 구현 및 검증

- 마이그레이션: `docs/sql/2026-09-15-marketing-registered-organizations.sql` (reviewer-delegation 이후 적용).
- 조회: `GET /api/marketing/organizations?q=회사명&page=1` 또는 `?id=회사ID`. 표준명·승인 별칭·법인 표기 변형을 검색하며 25건씩 제공한다. 유사성은 검색 후보 기준이며 동일 법인 확정 근거가 아니다.
- 등록: `POST /api/marketing/organizations`의 `action: create`. 기존 수정 API는 유지한다.
- Contact 폼: `POST /api/marketing/submissions`의 `mode: form`, 행별 `organizationId`·`organizationVersion`. Excel 접수는 기존 계약을 유지한다.
- SQL 테스트: `scripts/check-marketing-registered-organizations.sql` — 접근 거부, 별칭 검색, 회사 생성·중복/별도 법인, 재시도, 선택 ID/버전, 출처 위조 방지, 동명 ID 변경 감지, 미등록 회사 승인 차단, 등록 회사 승인, 회사 없이 반려, 감사 기록 실패 롤백.
- UI/API 테스트: 회사 선택 필수·기존 ID 불러오기·선택 해제·키보드 선택·늦은 응답 무시·별도 등록·서버 검증·검수 회사 우선 선택 및 기존 제출/검수 흐름을 확인한다.

## 운영 반영 기록

- 관련 UI/API 회귀 테스트 32개 통과. 타입 검사·ESLint·production build 통과. 로컬 실제 컴포넌트를 Chrome에서 열어 검색·선택·등록 화면과 제출 활성화 조건을 확인했으며 브라우저 예외가 없었다.
- 로컬 SQL 테스트와 마이그레이션 재적용 통과. 운영의 기존 제출/검수 함수가 확인한 기준 SQL과 같은지 비교한 뒤 마이그레이션을 적용했다.
- 운영 반영 전후 Master·회사·기존 제출 값의 전체 행 해시가 동일하다. 기존 요청의 신규 선택 ID는 null을 유지한다. 김하연 인증 역할에서 회사 검색 RPC가 정상 동작하고 메가존 검색 후보 3건을 반환함을 확인했다.
- 운영 배포 `dpl_hxt7tfZG7qP8eC4EXkM9eyYo292C` READY 및 `inje-playground.vercel.app` 연결 확인. 비로그인 회사 검색·등록 API는 401로 차단된다. 첫 배포의 권한 오류 후 프로젝트 팀을 명시한 재시도로 배포를 완료했다.
