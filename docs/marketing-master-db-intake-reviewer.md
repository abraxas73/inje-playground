# 오류 Contact 접수 및 담당 검수자 지정

2026-09-14. 최초 요구사항 재점검에서 확인한 두 항목에 대한 후속 구현·운영 설정이다.

## 1. 오류 Contact도 확인 필요로 수집

- 회사명·성명·이메일 누락, 이메일 형식 오류, 확인일 오류가 있어도 단건/Excel 제출을 저장한다.
- 검수 분류는 **확인 필요**이며 오류 근거를 함께 저장한다. 중복도 있으면 중복 근거를 추가하되 확인 필요 분류를 유지한다. 검수 화면에서 다시 검사해도 같은 우선순위를 적용한다.
- 원래 입력값(`submittedData`), 원래 지정 DB ID, 파일·시트·행·원문 등 출처를 보존한다.
- Excel 결과에서 ‘접수 완료 · 확인 필요’와 오류 내용을 확인할 수 있다.
- **승인 시에는 회사명·성명·유효한 이메일 등의 최종값 제약을 그대로 적용한다.** 미보완 Contact는 Master에 반영되지 않는다.
- 손상 파일·지원하지 않는 셀·잘못된 데이터 구조·존재하지 않는 명시 DB ID 등은 여전히 접수 실패로 반환하며, Excel은 해당 행을 수정해 다시 제출할 수 있다.

## 2. 김하연 검수 권한 지정

- 대상: **김하연 / hyk@innogrid.com / 커뮤니케이션팀**.
- 일반 사용자 역할은 그대로 두고 마케팅 검수·승인·반려 권한만 지정한다.
- 강승억·김하연 두 계정만 마케팅에 접근하는 기존 정책을 유지한다. 다른 사용자/관리자로 접근 범위를 넓히지 않는다.
- 기존 `marketing_set_reviewer` 함수를 통해 변경하여 지정자·시각·대상·사유가 변경 이력에 기록된다.
- 운영 설정 SQL: `docs/sql/2026-09-14-marketing-reviewer-kim.sql`. 승인된 계정의 ID·이메일·이름·역할을 검사하고, 이미 지정되어 있으면 중복 감사 기록을 만들지 않는다.

## 검증

- 관련 API·규칙·검수 UI·Excel 테스트 **31개** 통과(원본 파일 대조 포함). 누락/형식 오류 접수, 중복 시 확인 필요 유지, 검수 재조회 시 우선순위, 원본 보존, 구조 오류 접수 거부를 확인했다.
- TypeScript와 변경 범위 ESLint 검사 통과.
- 별도 로컬 PostgreSQL에서 일반 사용자를 검수자로 지정한 뒤 오류 제출 저장 → 미보완 승인 거부 → 값 보완 후 승인 → 원본 오류값과 승인자 감사 추적을 검증했다. 테스트 자료와 권한 변경은 롤백했다.
- SQL 수용 테스트: `scripts/check-marketing-intake-reviewer.sql` (별도 로컬 DB 전용).
- 운영의 실제 계정별 접근/검수 권한은 DB 권한 함수로 확인한다. 김하연의 로그인 세션을 대신 사용하거나 운영 Contact를 시험 승인하지 않는다.
