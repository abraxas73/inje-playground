# DB 관리 규칙 및 필터 결과 Excel 다운로드

1차 관리 규칙·다운로드 기능의 기록이다. 원본 규칙 편집과 Master 선택 검증의 후속 구현은 [관리 규칙 수정 및 Master DB 선택 검증](marketing-rule-management-v2.md)을 참고한다. 아래 1차 기능 설명 중 원본 규칙 잠금·샘플 전용 검증 제한은 후속 구현에서 해소했다.

## 사용 방법

Master DB의 18개 개별 컬럼 헤더를 클릭하면 해당 컬럼으로 오름차순 정렬하고, 같은 헤더를 다시 클릭하면 내림차순으로 전환한다. 기본값은 DB ID 오름차순이다. 선택된 헤더의 화살표가 현재 방향을 표시하며 키보드 Enter/Space로도 조작할 수 있다. 상위 그룹 헤더는 정렬 대상이 아니다.

정렬은 필터 결과 전체에 적용하고 페이지를 1로 되돌린다. 가로 스크롤 위치와 필터는 유지한다. 회사명·분류는 현재 회사·기관 기준값으로, 나머지는 표시 필드값으로 정렬한다. 텍스트는 앞뒤 공백·대소문자를 무시하고, 빈 값은 양방향 모두 마지막에 둔다. 동일 값은 DB ID·내부 ID 순으로 고정해 페이지 간 중복/누락을 방지한다. `YYYY-MM-DD` 날짜는 시간 순서로 정렬된다. Excel 다운로드도 같은 정렬을 적용하며 `조회 조건` 시트에 기준·방향을 기록한다.

`/marketing`은 Master DB로 열린다. 검색어·회사 분류·내부 관리부서·정비 필요 필터를 설정하고 **필터 결과 Excel 다운로드**를 누르면 현재 페이지에 관계없이 전체 결과를 내려받는다. 원본과 동일한 18개 컬럼, 5개 그룹/2줄 헤더, 원본 형태의 DB ID와 연락처를 유지한다. `조회 조건` 시트에 적용 조건·건수·한국 시각을 기록한다. 다운로드 요청 시점의 승인된 Master를 한 DB 조회에서 가져오므로 페이지별 응답을 이어 붙이지 않는다. 조회 실패나 일부 행만 반환된 경우에는 파일을 만들지 않는다.

상단 **Contact 등록**은 Form 단건 등록이며, Master 상세의 **변경 정보 제출**은 Form 수정 요청이다. Excel 제출과 동일한 접수·검증·담당자 승인 경로를 사용한다.

**관리 규칙**에서 원본 관리기준과 추가 규칙을 조회한다. 검수 담당자는 **규칙 추가**로 다음을 설정한다.

- 규칙 이름과 안내, 검사할 Contact 항목
- 필수값, 이메일, 날짜, 허용값, 금지값, 최대 길이, 담당자 확인 중 검증 방식
- 항상 적용 또는 특정 항목이 입력되었거나 특정 값일 때만 적용하는 조건
- 오류(승인 차단) / 확인 필요(근거 기록), 활성 여부와 변경 사유

예: `Eco 여부 = Y`일 때 `Eco ID 필수`, `내부 관리부서 허용값 = 마케팅실 / 사업실`. 값 비교는 앞뒤 공백과 대소문자를 무시한다. 필수값 이외 이메일·날짜·최대 길이는 빈 값을 허용하므로, 필요하면 별도의 필수값 규칙을 추가한다. 허용값은 빈 값이 목록에 없으면 미충족이다. 사용자 코드·SQL·정규식 실행은 제공하지 않는다.

추가 규칙은 수정하거나 비활성화할 수 있다. 원본 관리기준과 기본 보호 규칙은 보존하며, 변경 전후 내용·버전·작성자·사유를 이력에 남긴다. **저장된 규칙 시험 검증**은 Contact를 저장하지 않고 활성 규칙만 실행한다. 기존 Master 중복 비교는 실제 제출·검수 과정에서 수행한다.

## Excel `02_관리기준` 대조

원본 3~14행을 13개 규칙 항목으로 등록했다. 등록기준 3행은 회사명 자동 검사와 담당자 실재 확인으로 나눴다. 기존 필수정보/이메일 형식 검사 3개를 더해 초기 등록은 16개다.

| 원본 행 | 관리기준 | 실행/관리 방식 |
|---|---|---|
| 3 | 소속 식별·실제 관리 가능한 Contact | 회사명 필수 자동 검사 + 소속/관리 대상 담당자 확인 |
| 4 | 발송 유효성 정제 | 수신거부·자동삭제·Hard Bounce·최근 3개월 연속 Soft Bounce 제외 여부를 담당자가 자료로 확인. Stibee 미연계로 자동 판정하지 않음 |
| 5 | 고유 DB ID·중복 생성 방지 | 기존 고유 ID, 이메일 제한, 회사·성명 비교 및 승인 직전 충돌 검사 |
| 6 | 기업 외 공공·단체·언론·대학 등 포함 | 회사·기관 공통 모델과 분류 기준으로 관리 |
| 7 | 회사명 표기 통일·상이한 법인 보존 | 표준명/승인 별칭 추천, 동일 법인 불명확 시 확인 근거 필요 |
| 8 | 불확실한 분류 보류 | 회사 분류·확인 상태에서 `확인 필요` 유지 |
| 9 | 회사·기관 단위 분류 | 회사의 분류를 소속 Contact에 공통 적용 |
| 10 | 원본출처·원본시트 유지 | 이관 원본/제출 원문·시트·행 및 변경 이력 보존 |
| 11 | 별도 Eco 체계·미확정 정보 입력 금지 | Eco 5개 필드 중 값이 있을 때 확정 자료 여부를 담당자 확인. 외부 DB 자동 조회 없음 |
| 12 | 확인된 정보만 수정 | 최종값 확인 근거를 기록한 검수 승인 필요 |
| 13 | 이동·퇴사·회사명 변경 시 업데이트 | 변경 Form/Excel 제출 → 검수·승인. 인사 이동/퇴사 자동 감지는 하지 않음 |
| 14 | 최종확인일 `YYYY-MM-DD` | 실제 달력 날짜 검사. 실제 검증일을 입력하며 접수/다운로드 날짜로 덮어쓰지 않음 |

`기본 관리 절차` 유형은 DB 제약·회사 모델·원본 보존·중복 검사 등 기존 처리와 연결된 기준이다. 매 Contact에서 참/거짓을 반환하는 추가 필드 규칙과 구분해 표시한다. 발송 유효성·사실 확인의 실증 자료는 사람이 확인한다. 모든 기준을 자동으로 증명하는 기능은 아니다.

기존 Excel에서 이관한 7,294건은 과거 원본 보존 대상이다. 소속·성명 등의 기존 누락 자료를 삭제하거나 모두 유효하다고 재판정하지 않는다. 새 규칙은 다음 제출/재검증/승인에 적용하며 기존 Master를 일괄 수정하지 않는다. AI는 계속 비활성이고 외부 Stibee/Eco 동기화는 후속 범위다.

## 검증 및 승인

Form·Excel 모두 규칙 엔진 `marketing_validate_rules`를 사용한다. 자동 검사 미충족은 확인 필요로 접수하고, 오류 등급이면 보완 전 승인을 차단한다. 일반적인 담당자 확인 항목은 신규/업데이트/중복 의심 분류를 유지하면서 승인 단계의 확인 목록으로 전달한다.

최종값 재검증과 승인에서 최신 규칙을 다시 검사한다. 승인 직전에는 DB가 직접 규칙을 실행하므로 API/UI를 우회해도 오류를 통과할 수 없다. 확인 항목·충돌은 근거 기록이 필요하고, 규칙 버전이나 최종값이 바뀌면 기존 확인 토큰이 무효화된다. 규칙 변경과 승인은 같은 트랜잭션 잠금으로 직렬화한다. 반려는 규칙 미충족 상태에서도 가능하다.

검증 기록에는 당시 활성 규칙의 정의·버전·결과를, 승인 이력에는 최종 적용 규칙과 담당자 근거를 저장한다. 규칙 변경 이력은 별도 보존한다. 추가 규칙 수정은 버전을 비교해 다른 담당자의 변경을 덮어쓰지 않는다.

## 구현과 권한

- DB: `marketing_rules`, `marketing_rule_history`, `marketing_save_rule`, `marketing_validate_rules`; 기존 `marketing_review_check`, `marketing_review`, `marketing_safe_validation` 확장
- API: `/api/marketing/export`, `/api/marketing/rules`; 기존 제출/검수 API 공통 규칙 실행
- UI: 필터 결과 다운로드, 관리 규칙 목록·추가·수정·비활성화·시험 검증·이력, 승인 확인 목록
- 페이지/API/DB는 기존 강승억·김하연 제한을 유지. 규칙 변경은 검수 담당자에게만 허용하며 테이블 직접 쓰기는 차단
- SQL 적용 순서: 기존 completion → `2026-09-14-marketing-export.sql` → `2026-09-14-marketing-rules.sql`. 운영 원본 Contact를 수정하지 않는 스키마/규칙 이관이다.
- 정렬 후속 SQL: `2026-09-14-marketing-sort.sql`. 기존 검색 RPC에 정렬 항목·방향을 추가하며 기존 호출의 기본값과 RLS를 유지한다. 정렬 키는 허용된 18개만 사용하며 동적 SQL은 실행하지 않는다.
