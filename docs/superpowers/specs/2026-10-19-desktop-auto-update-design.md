# 이노크루 데스크톱 자동 업데이트

## 사용자 요구와 확정된 동작

대상은 macOS와 Windows이다. 2026-10-19 사용자 설명에 따라 다음 흐름을 사용한다.

1. 앱 프로세스를 시작하면 업데이트를 한 번 확인한다. 인증이 필요한 조회는 앱 세션 복구 후 수행한다.
2. 시스템 메뉴 `About 이노크루` 바로 아래 `업데이트 확인…`에서도 다시 확인한다.
3. 새 버전이 있으면 모든 앱 화면 맨 위에 업데이트 띠를 표시한다.
4. 사용자가 띠의 업데이트를 한 번 누르면 앱이 다운로드, 검증, 기존 프로세스 종료, 설치, 새 프로세스 실행을 연속 처리한다.
5. 다운로드 후 별도의 `업데이트 적용` 버튼이나 설치·재시작 확인 창을 요구하지 않는다.
6. 다운로드 폴더의 EXE/DMG를 사용자가 직접 실행하게 하지 않는다. 브라우저를 열지 않는다.

띠를 누르는 것이 설치와 재시작에 대한 동의이다. 버튼 주변에 `완료되면 앱이 자동으로 재시작됩니다. 작성 중인 내용은 먼저 저장하세요.`를 표시한다. 업데이트 발견만으로 앱을 종료하지 않는다. 로그인·설정·사용자 파일은 제거하지 않는다. 저장되지 않은 모든 WebView 입력을 자동 저장한다고 약속하지 않는다.

## 구현자가 선택한 구조

앱 교체·서명 검증·설치 수명주기를 직접 셸 스크립트로 재구현하지 않는다. macOS는 Sparkle 2.10.0의 사용자 정의 UI 드라이버, Windows는 WinSparkle 0.9.4의 즉시 설치 API와 기존 Inno Setup을 사용한다. Flutter와 네이티브 어댑터 사이의 작은 채널을 직접 구현한다. 현재 범용 Flutter auto_updater API에는 필요한 일괄 설치 제어가 충분하지 않아 그대로 사용하지 않는다. 두 버전은 2026-10-19 공식 GitHub latest release에서 확인했으며 lockfile/다운로드 checksum으로 고정한다.

- Flutter: 업데이트 확인/발견/진행/실패 상태와 전역 띠, 중복 클릭 차단, 수동 확인 결과 안내.
- macOS: Sparkle 사용자 정의 UI를 Flutter 띠에 연결한다. 사용자의 시작 요청이 있는 세션에만 다운로드와 설치·재실행 응답을 자동 진행한다. 새 설치 동의 창은 추가하지 않는다.
- Windows: 시작 버튼에서 `win_sparkle_check_update_with_ui_and_install()`을 호출한다. 라이브러리의 네이티브 진행 창은 허용하되 추가 설치 동의를 요구하지 않는다. Flutter 띠에도 진행 상태를 유지한다. 네이티브 어댑터가 정상 종료를 요청하고 Setup이 파일 교체 및 자동 재실행을 수행한다.
- macOS 샌드박스를 끄지 않는다. Sparkle의 샌드박스 지원 설치 서비스와 서명 설정을 적용한다.
- 기존 iOS/Android 업데이트 동작은 변경하지 않는다.

## 메뉴와 표시

- macOS: 기존 앱 메뉴 About 항목 바로 아래에 삽입한다.
- Windows: 창 시스템 메뉴에 `About 이노크루`, 바로 아래 `업데이트 확인…`을 제공한다.
- 앱 루트에 데스크톱 띠를 배치해 WebView 등 탭 외부 경로에서도 보인다. 기존 TabShell 띠는 중복되지 않게 이동한다.
- 수동 확인은 최신 버전, 로그인 필요, 네트워크 오류를 구분한다. 자동 확인 실패는 앱 사용을 막지 않는다.
- 띠 상태: `새 버전 {version} · 업데이트` → `업데이트 진행 중…` → `설치 후 다시 시작합니다…`. macOS는 제공되는 다운로드 진행률을 표시하고 Windows는 네이티브 진행 창에서 상세 진행률을 제공한다.
- 업데이트 중 반복 확인/클릭은 같은 작업을 보여줄 뿐 두 번째 설치를 시작하지 않는다.

## 배포 신뢰와 인증

공식 오리진은 `https://innocrew.innogrid.com`이다. 기존 사내 사용자 인증 및 private Storage 정책을 유지한다.

- 현재 `desktop_app_release`의 버전/파일명/경로/SHA-256/크기에 업데이트 서명, 빌드 번호, 최소 OS 정보를 추가한다. 업데이트 정보 없는 기존 릴리스는 자동 실행하지 않는다.
- macOS/Windows 각각의 Ed25519 공개키를 앱에 고정한다. 개인키는 릴리스 담당자의 보안 저장소/CI secret에만 저장한다. 키 없이 서명 없는 업데이트로 우회하지 않는다.
- macOS는 기존 Developer ID 서명·공증도 계속 적용한다. Windows 업데이트 서명은 Authenticode 인증서와 별개이며 SmartScreen/조직 정책을 우회하지 않는다.
- 플랫폼별 인증된 appcast와 고정 버전 artifact 스트림을 같은 공식 오리진에서 제공한다. 서버가 private Storage의 파일을 스트리밍하고 클라이언트를 Storage로 리다이렉트하지 않는다.
- 네이티브 업데이트 요청에 사용하는 Bearer 토큰은 메모리에만 전달한다. URL, appcast, 명령행, 진단 로그에 넣지 않는다. 업데이트 시작 전에 세션을 갱신하고, 인증 만료/로그아웃 시 새 작업을 막는다.
- appcast의 artifact 오리진·플랫폼·버전·서명·크기를 검증한다. 인증 헤더를 외부 호스트로 전달하는 리다이렉트는 허용하지 않는다. 현재 릴리스가 도중 바뀌어도 버전을 고정해 파일/서명 혼합을 막는다.
- 과거 버전과 동일 버전 설치, 누락된 서명, 변조된 다운로드는 거부한다.

## 종료와 재시작

설치 엔진이 다운로드·검증을 끝내기 전에는 앱을 종료하지 않는다. 네이티브 종료 요청은 현재 앱 인스턴스에만 보낸다. 이름으로 모든 프로세스를 강제 종료하거나 다른 프로그램을 종료하지 않는다.

Windows Setup은 자동 업데이트 전용 인자를 인식해 대화 없이 기존 설치 위치를 업데이트하고, 성공한 경우 새 앱을 한 번만 실행한다. 기존 수동 Setup 설치 흐름도 유지한다. 파일 사용 중/종료 실패를 무시하고 설치 완료로 처리하지 않는다.

macOS는 Sparkle 설치 서비스가 앱 교체와 재실행을 담당한다. 읽기 전용 DMG 실행 상태나 권한 부족은 설치 엔진이 지원하는 경로로 처리하고 필요한 OS 권한 창은 허용한다. OS 보안·관리자 승인을 건너뛴다고 약속하지 않는다.

다운로드/검증 실패는 기존 앱을 종료하지 않고 오류 및 재시도를 표시한다. 설치 중 실패 시에는 엔진의 복구 결과를 확인하고 복구 불가능한 상태를 성공으로 숨기지 않는다. 로그인 데이터 삭제나 무조건 재설치는 없다.

## 마이그레이션과 배포

1.7.7 이하에는 이 기능이 없으므로 자동 업데이트 기능을 포함한 최초 버전은 기존 방식으로 한 번 설치해야 한다. 그 다음 버전부터 원클릭 자동 업데이트가 가능하다. 새 기능이 이전 설치본에 소급 적용된다고 안내하지 않는다.

이번 기능은 앱 네이티브 코드, 웹 배포 API, 서명·게시 파이프라인이 한 세트이다. 서명된 설치본의 실제 업그레이드 검증이 끝나기 전 자동 업데이트 가능 릴리스로 게시하지 않는다. 출시 버전은 구현 시작 시 최신 main/게시 버전을 다시 확인하여 정한다.

## 완료 기준

- 시작/메뉴 확인, 최신 버전/오프라인/미로그인 구분, WebView에서도 띠 표시.
- 업데이트 클릭 한 번 후 다운로드·검증·정상 종료·설치·새 프로세스 실행까지 두 번째 사용자 클릭 없음(OS 권한 확인 제외).
- 손상 파일/잘못된 서명/외부 주소/만료 인증/중복 클릭/다운로드 중 로그아웃/설치 중 릴리스 변경 테스트.
- macOS 샌드박스 활성·공증 빌드, Windows 설치본 각각 이전 테스트 버전→새 테스트 버전의 실제 업그레이드 검증. 기존 PID 종료, 새 PID 및 버전, 로그인·설정 보존 확인.
- 다운로드 실패와 앱 종료 실패가 기존 앱을 손상시키지 않는지 확인. 네이티브 런타임 미검증 항목은 정적/단위 테스트 통과와 구분해 보고.
- Windows 대화형 환경이 없으면 빌드 성공만으로 실기기 업그레이드 완료라고 보고하지 않는다.

## 설계 검토

독립 builder-check는 원클릭 설치·재시작, OS 권한 예외, 인증/서명, 정상 종료/복구 범위를 검토했고 계획 수립을 막는 미해결 사용자 선택이 없다고 판단했다. 네이티브 API·설치 동작은 구현 및 실제 업그레이드 시험에서 검증해야 한다.
