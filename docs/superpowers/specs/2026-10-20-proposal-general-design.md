# 제안도우미-일반현황 설계 (2026-10-20)

요청: Confluence AXTF「[제안] 제안서 내 공통 항목 페이지 자동 생성 기능」(2361393574) + 사용자 보충 설명.
제안서마다 들어가는 회사 일반 현황(인력·사업 실적·재무/신용등급 등)을 **고객사 템플릿에 맞춘 PPT**로 자동 생성한다.

## 1. 사용자 결정 (2026-10-20)

| 항목 | 결정 |
|---|---|
| 메뉴명 | **제안도우미-일반현황** (웹 메뉴 '업무' 그룹, 앱 메뉴도 같은 키) |
| 메뉴 권한 | user 이상 기본 허용, 관리자가 사용자별로 끌 수 있음(페이지 권한) |
| 일반현황 PPT 등록 | 이 메뉴를 쓰는 사람 누구나 새 버전 등록. **최신이 기본**, 옛 버전도 골라 쓸 수 있음 |
| 적용 방식 | **둘 다, 생성할 때 선택**: ① 모양 유지(고객사 겉모습만 입힘) ② 고객사 레이아웃으로 재구성(AI) |
| 결과물 | 내 생성 이력에 보관 + 공유 — PPT 만들기와 같은 동작(공유하면 다른 사람 목록에 보이고, 다른 사람이 공유한 것도 본다) |
| 프로젝트명 | 업로드할 때 **필수**(1~100자). 결과·공유 목록의 제목 — 처음엔 "고객사명"이었다가 "프로젝트명"으로 정정 |

## 2. 화면 `/proposal/general`

- **새로 만들기**: 프로젝트명(필수) · 고객사 템플릿 업로드(.pptx/.potx, 20MB) · 일반현황 버전 선택(기본 최신) · 적용 방식(모양 유지 / 레이아웃 재구성) → 생성.
- **목록 탭**: 내 결과 / 공유된 결과(누구나, `share_enabled`인 것만). 행 = 프로젝트명 · 일반현황 버전 · 방식 · 상태 · 만든 사람 · 날짜.
- **상세 `/proposal/general/[id]`**: 다운로드, 공유 켜기/끄기(링크 복사), 다른 방식·다른 버전으로 다시 만들기, 삭제(내 것만).
- **일반현황 버전 관리**(같은 페이지 한 섹션): 버전 목록(제목·기준일·장 수·올린 사람·날짜, 최신 표시), 새 버전 올리기(제목·기준일·파일), 숨기기(삭제 없음 — 옛 결과가 참조).

## 3. 데이터

- `proposal_profiles` — 일반현황 PPT 버전: `id, title, as_of date, storage_path, slide_count, uploaded_by, created_at, hidden`. 최신 = hidden 아닌 것 중 `created_at` 최댓값.
- `proposal_jobs` — 생성 이력: `id, owner_id, project_name(필수, 1~100자), profile_id, template_path, mode('restyle'|'reflow'), status('queued'|'running'|'done'|'failed'), result_path, error, share_enabled, share_token, created_at, finished_at`.
- 버킷 `ppt`의 `proposal/` 아래(profiles·templates·results). RLS: 프로필은 메뉴 권한 있는 사용자 읽기, 잡은 본인 + `share_enabled` 읽기. 쓰기는 서버 API(service role)로만.
- 페이지 키 `proposal` 추가 → DB 함수 키 목록 SQL 후속 파일 + 드리프트 테스트.

## 4. 생성 엔진 (ppt-service 새 엔드포인트, 패키지 `innogrid_ppt`는 수정하지 않음)

### ① 모양 유지 `restyle`
고객사 템플릿 파일을 바탕으로, 일반현황의 장표마다 고객사의 '제목만' 레이아웃(없으면 가장 단순한 레이아웃)으로 새 장을 만들고:
- 제목 → 고객사 제목 자리표시자, 나머지 도형·표·그림·차트 → **벡터 그대로 이식**(기존 transplant 방식, 그림·차트 관계 복사).
- 고객사 슬라이드 크기·본문 영역에 비율 유지로 맞춤, 글꼴은 고객사 테마 글꼴(+mj/+mn), 우리 브랜드 파랑 → 고객사 accent1.
- 템플릿에 있던 예시 장표는 지운다. 숫자·표 내용은 원본 그대로.

### ② 레이아웃 재구성 `reflow`
1. `/extract`로 일반현황 장표의 제목·본문·표·그림 목록을 뽑는다.
2. 새 `/proposal/layouts`로 고객사 템플릿의 레이아웃 목록(자리표시자 종류·위치·크기)을 받는다.
3. Claude가 장표별로 레이아웃·자리 배치 JSON을 만든다(숫자·고유명사는 원문 그대로, 새 사실 생성 금지 — 프롬프트 규칙 + 서버 검증: 결과의 숫자 토큰이 원본에 있는지).
4. `/proposal/build`가 그 JSON으로 고객사 레이아웃에 채운다(표는 본문 자리 크기에 맞춰 새로 그림, 그림은 비율 유지). 넘치면 글자 축소 → 장 분리.

두 방식 모두 생성은 `after()` 백그라운드(PPT 만들기와 같음), 상태 폴링.

## 5. 권한·보안
- 업로드: pptx/potx만, 20MB, 압축 해제 크기 검사(기존 `checkXlsxArchive`와 같은 방식), 매크로(pptm)·외부 링크 거부.
- 공유 토큰·서명 URL은 로그·감사 detail에 넣지 않는다. 감사 카테고리 `proposal`(건수·모드만).
- 고객사 템플릿·결과는 업로드한 사람과 공유받은 사람만.

## 6. 범위 밖(이번에 안 함)
- 일반현황 *데이터*(인력 수·실적 표)를 DB에서 자동으로 최신화 — 지금은 사람이 최신 PPT를 올린다.
- 일반현황 중 일부 장만 골라 만들기 → 다음 단계 후보(장 선택 체크박스).

## 7. 검증
- ppt-service pytest: 샘플 고객사 템플릿 2종(16:9·4:3) × 두 방식, 장 수·이식 도형 수·글꼴·슬라이드 크기·PowerPoint 복구 경고 유발 요소(id 중복) 검사.
- 웹 vitest: API 권한·업로드 검증·최신 버전 선택·공유 목록.
- 실제 파일로 결과 확인: **현재 일반현황 PPT 1개 + 실제 고객사 템플릿 1~2개가 필요**(픽스처에는 넣지 않고 로컬에서만).
