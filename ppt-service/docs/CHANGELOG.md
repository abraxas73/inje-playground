## v3.1 — 템플릿 v1.0 최신본 재배포판 (2026-09-17 갱신) 반영

디자인센터가 같은 106장 구성으로 템플릿을 다시 배포했다. 슬라이드 수·순서·노트는 그대로이고
도형 지문 대조로 31장에서 미세 조정이 확인됐다 — 전부 **키워드 칩과 설명 박스 칩 타이틀의 크기·위치**다.

- 키워드 칩: 2.11 × 0.78 → **1.90(1.93) × 0.74**. 칩 y가 장표별로 0.01~0.17cm 이동
  (`pill-4-msg`·`pill-3-msg` 10.99 → 11.16, `pill-3` 10.63 → 10.72, `pill-3-note` 9.73 → 9.82, `stack-3` 5.05 → 5.12 등).
- 설명 박스 칩 타이틀: 3.32 × 0.64 → **3.14~3.35 × 0.68**. y가 0.02~0.06 이동 (`table-note` 12.54/13.53 → 12.60/13.61 포함).
- `table-lower` 위 설명 본문 상자 1.44 → 1.97 (용량 증가).
- 이 도구는 칩 폭·여백을 **그 도형에서 읽어** 쓰므로 코드 변경은 없고 `tokens.LAYOUTS` 좌표 31곳과 `capacity.py` 재측정만 반영했다.
  이전 좌표도 허용오차(0.25cm) 안이라 동작에는 차이가 없었지만, 실측값 원칙대로 맞췄다.

### 슬라이드 노트 → 코드 (누락 금지 규칙)

최신본 노트를 전수 읽어 규칙으로 옮겼다. 전체 대응표는 `TEMPLATE_ANALYSIS.md` §3-1. 이번에 새로 들어온 것:

- **하단 텍스트 박스는 하단 고정, 위쪽으로 커진다** (노트 27~64·84·88·89). `reflow.resize_bottom_fixed()`.
  마무리 문구가 두 줄이면 박스가 위로 커지고(가이드 12·13), 한 줄이면 두 줄 바를 한 줄 높이(메세지형 02-2)로 줄인다(노트 28·29).
- **메세지형은 두 줄까지** (`CLOSING_MAX_LINES`). 세 줄이면 빌드가 막는다.
- **형제 박스는 가장 큰 박스 기준으로 맞춤** — 카드 늘리기(`_equalize_row`)와 설명 박스(`_fit_note_boxes`) 둘 다.
- **표의 열 폭은 글자수, 행 높이는 줄 수** (노트 85~87). `table._auto_col_widths()` · `_auto_row_heights()`.
  자리를 넘치면 7.5pt로 재시도, 그래도 넘치면 오버플로.
- **목차 6~8개는 같은 장 위쪽에 행을 추가** (노트 23). 이전의 "두 장으로 나누기"는 노트와 달라 폐기했다.
- **표지 부제목은 제목 줄 수에 맞춰 이동** (노트 22). 제목 1~3줄. **부서명 미상이면 "부서명"** (`DEFAULT_DEPT`). `meta.author` 추가.
- **차트 항목은 도넛·막대 모두 5개까지** (노트 82~84).
- **`card-3-chips`는 본문 항목 6개 이상일 때만** (노트 30) · **`compare-vs` 본문 3~4개 권장** (노트 70) — 권고.
- **flow의 행 수가 줄면 남은 행이 자리를 나눠 갖는다** (노트 75·76 "개수에 따라 박스 크기 조정"). `flow-4` + `reflow.stretch_rows()`.
- KPI형 (가이드 19): `kpis: [{desc, value}]` 키.
- 날개가 '제목 + 설명' 카드인 장표(73·74·83): `left/right: [{title, body}]`.
- '01. 제목' 형 카드(58~60·64·66): 번호를 안 쓰면 자동으로 붙인다 (`numbered_title`).

### 표준 프롬프트(최신본) → 코드

- **본문이 많으면 8pt까지 축소 허용** — 상자를 늘릴 자리가 없을 때만 8pt로 줄인다 (`_fit_or_grow`, `BODY_PT_MIN=8`).
  `slots.capacity_of()`가 8pt 기준 용량을 같은 식으로 다시 잰다 (`lnSpc`가 절대값이면 줄 수가 늘지 않는 것까지 반영).

- PPT 원고 규칙(장표 순서 유지 · 강조 가시화 · 표는 템플릿 스타일)은 CLAUDE.md §2-6에 작업 규칙으로.

## v2.0 — 템플릿 v1.1 (디자인가이드 병합본 · 86장) 대응

템플릿이 33장 → 86장으로 바뀌면서 번호·좌표가 전부 달라졌다. **v1.0용 deck.yaml은 그대로 돌지 않는다** —
아래 이름 대응표를 보고 고쳐야 한다.

### 템플릿 쪽 변경

- **디자인 가이드와 템플릿이 한 파일로 병합됐다.** 1~20장이 가이드(컬러·서체·로고 표기법·
  가이드라인·컴포넌트·체크리스트)다. 산출물에는 들어가지 않는다.
- **본문 레이아웃이 24종 → 46종으로 늘었다.**
- **간지에 '하위 섹션형'이 생겼다** (원본 24). `sections[].subs`를 주면 자동으로 선택된다.
- **제품 소개 페이지 12종이 들어왔다** (원본 74~85). 제품명만 지정하면 삽입된다.
- **자유 배치 장표가 생겼다** (원본 72·73). 템플릿으로 표현하기 어려운 원고용.
- 색 이름이 가이드 기준으로 정리됐다: Primary `#0150FF` · Navy `#002060` ·
  Sky Blue 01 `#DDEBFF` · 02 `#EBF3FF` · 03 `#F3F8FF` · Blue 200 `#3FC4FF` · Text Dark `#0D0D0D`.
- 제품 지정색에 MLOps(AI큐브잇 `#00C18C`)가 명시되고 HCP(옵티머스잇 `#70DE68`)가 정리됐다.
- **본문 장표의 줄간격 % 사용이 사라졌다.** v1.0에서 "정상"으로 넘기던 검사 예외가 없어졌다 —
  이제 위반이 나오면 진짜 문제다.

### 도구 쪽 변경

- **좌표계가 절대(화면) 좌표로 바뀌었다.** `geom.py`가 그룹 변환(`chOff`/`chExt`)을 풀어 낸다.
  v1.0의 "XML 좌표 ≠ 화면 좌표" 함정(8·12·13·18·26·30번 배율, 11번 오프셋)이 사라졌다.
  v1.1 템플릿은 카드마다 그룹을 하나씩 두어 **그룹 안 형제들이 x를 공유**하므로
  (27번 카드 3개의 자식 x가 전부 0.75) 이 처리 없이는 카드 순서가 뒤섞인다.
- **장표를 선언적 스펙으로 기술한다.** `tokens.LAYOUTS`에 한 덩어리를 적으면 한 벌의 엔진이
  채운다. 46종을 각각 손으로 짜지 않는다.
- **슬롯 귀속을 '가장 가까운 밴드'로 판정한다.** 밴드끼리 1mm밖에 안 떨어진 곳이 있어
  (50~52번의 4.86 헤더 vs 4.96 소제목) 허용오차만으로는 가를 수 없다.
- **오버플로 판정이 줄 수 기준으로 바뀌었다.** `capacity.py`가 템플릿 상자를 실측해
  "한 줄 몇 자 × 몇 줄"을 갖고 있고, 각 문단이 몇 줄로 접히는지 더해서 비교한다.
  글자 총수로는 못 잡던 문제(불릿 3개는 짧아도 3줄)가 해결됐다.
  `tools/measure.py`로 다시 잰다.
- **마무리 문구의 강조색 허용 여부를 템플릿에서 자동 판정한다.** 어두운 바(그라데이션·검정·
  Primary) 위 흰 글자에는 `[[강조]]`를 적용하지 않는다 — 파란 강조색이 파란 바에서 보이지 않던
  문제를 없앴다.
- **검사기가 제품 장표를 구조로 가려낸다.** 제품 기능 장표에는 제품명 글자가 아예 없어서
  문구로는 못 가른다 — 왼쪽 세로 제품 패널 그림(x≈1.35 · 폭≈6.5 · 높이≈11cm)으로 판별한다.

- **합쳐진 그룹의 기본 번호를 이어서 매긴다.** `steps-8`·`steps-10`처럼 두 줄로 나뉜 장표에서
  `num`을 생략하면 두 번째 줄이 01부터 다시 시작했다. 이제 06·07…로 이어진다.

### v2.1 — 템플릿 슬라이드 노트(가이드 1~20) 반영

디자인 가이드 구간의 노트를 뒤늦게 확인해 빠졌던 규칙 네 가지를 넣었다.

- **카드 3~6단** (노트 18·19 "카드는 3단부터 6단까지 활용가능"). `card-5` `card-6` 추가.
  가이드 실측 그리드(폭 8.74 / 6.50 / 5.17 / 4.26)로 4단 장표의 한 열을 복제해 다시 깐다.
  좌우 여백 0.50cm는 단 수와 무관하게 고정된다. **이전 문서의 "5카드 레이아웃이 아예 없다"는
  서술은 틀렸다 — 정정했다.**
- **타이틀 한 줄 + 부가 설명** (노트 8). `lead` 키 추가. 가이드 8번의 상자를 복제해
  y=3.20에 놓는다. 원고에서 설명이 타이틀 위에 있으면 템플릿 기준으로 뒤집는다.
- **본문 길이에 따른 가변 박스** (노트 13·14 "본문이 길어지면 박스도 아래로 같이 커집니다").
  넘치면 먼저 상자와 배경 카드를 늘리고, 같은 줄의 형제 카드도 같은 높이로 맞춘다.
  늘릴 자리조차 없을 때만 오버플로로 막는다.
- **서술형은 마침표 유지** (노트 13·14 "블릿형 본문은 마침표를 사용하지 않습니다. 서술형은 사용").
  yaml 리스트는 블릿형(마침표 제거), 문자열 하나는 서술형(유지)으로 가른다.
- **원고 그림 이식** (노트 16 "원본파일에 이미지가 있다면 원본파일에서 가져다 사용. 임의 삭제 X").
  `media.extract_images()` 로 뽑고 `images` 키로 넘기면 비율 유지·중앙 Crop·라운드 적용.

### v2.1.1 수정 — 칩 타이틀도 글자에 맞춰 늘어난다

노트 9는 **"칩타이틀과 키워드칩"** 둘 다를 말하는데 v2.1은 키워드 칩만 처리하고 있었다.

- **칩 타이틀**(설명 박스 제목, 검정 알약 `roundRect`)이 템플릿 고정 폭 3.32cm에 머물러
  짧은 글자엔 헐렁하고 긴 글자엔 두 줄로 접혔다. 이제 글자수에 맞춰 **우측으로만** 늘어난다.
- **여백을 상수로 박지 않는다.** 칩 타이틀 여백이 9pt 0.34cm · 10pt 0.46cm로 달라서,
  글자를 바꾸기 전에 그 도형이 쓰고 있는 여백을 재서 그대로 유지한다.
- **안전여유(글자 폭 4%, 최소 0.10cm) + `word_wrap=False`** 를 넣었다. 측정값과 실제 렌더
  폭 차이로 칩이 두 줄로 접히면 "위아래 고정"이 깨지기 때문이다.
- 바 타이틀(항목 Pill·패널 헤더, 폭 5.98~12.76)은 노트 9대로 **콘텐츠 폭을 따르므로
  건드리지 않는다.** 폭 5.0cm를 경계로 가른다.

### v2.1.2 수정 — 설명 박스가 내용에 맞춰 **줄고**, 하단 가이드라인에 맞는다

노트 13·14는 "본문이 길어지면 박스도 같이 커집니다"만 말하지만 반대도 참이다.
본문이 한 줄인데 박스가 다섯 줄 높이면 빈 공간이 그대로 남는다.

- **설명 박스가 내용 높이로 줄어든다.** 글을 다 채운 **뒤에** 실제 줄 수를 세므로
  늘어난 경우·줄어든 경우 모두 맞는다. 안쪽 여백(제목 위, 제목↔본문, 본문 아래)은
  템플릿 값을 읽어 그대로 유지한다.
- **바닥을 하단 가이드라인(15.35)에 맞춘다** (가이드 7 "가이드라인 안쪽으로 배치").
  템플릿의 하단 설명 박스는 전부 0.17~0.21cm 넘겨 놓여 있었다. 위쪽에 놓인 설명 박스
  (`table-lower`)는 하단 블록이 아니므로 위를 고정하고 아래만 줄인다.
- **나란한 박스는 같은 높이·같은 위치.** 템플릿이 형제끼리 0.03cm 다르게 그려 둔 곳이 있어
  줄 수만 맞춰서는 높이가 안 맞았다. 사이에 놓인 화살표도 같이 움직인다.
- **줄 높이를 상자마다 실측한다.** 1.3em 일괄 계산은 실제(9pt에서 14.5~14.8pt)보다 25% 작아
  네 줄짜리 본문이 상자 바닥에 붙었다. 이제 `a:lnSpc`·`a:spcAft`를 읽는다.
  `capacity.py`도 같은 기준으로 다시 생성했다 — **296개 중 52개가 줄었다.**
  이전 deck.yaml에서 오버플로가 새로 뜨면 글이 실제로 넘치고 있었다는 뜻이다.
- **칩은 줄 수로 막지 않는다.** 칩은 줄바꿈 없이 우측으로 늘어나므로(노트 9)
  "한 줄 5자" 같은 줄 수 판정을 적용하면 안 된다. 폭의 합으로만 본다.
- `tools/make_sample.py`가 `main_body`를 빠뜨려 `panel-note`·`panel-rows`·`split-3`
  예제의 오른쪽 설명이 비어 있던 것을 고쳤다.

### v2.2 — 원고 PPT의 도식을 그대로 이식한다

표준 프롬프트 "원고가 PPT 파일일 경우" 3항("템플릿으로 표현하기 어려운 내용은 원고의 레이아웃을
유지하되, 디자인 스타일은 이노그리드 템플릿에 맞추어 변경")을 실제로 할 수 있게 했다.
그동안 `free-title`은 빈 장표를 내놓고 "사용자가 직접 채우라"고 했을 뿐이다.

- **`source` 키 추가** (`free-title` · `free`). 원고 pptx와 장 번호를 주면 그 장의 도형을
  **벡터 그대로** 가져온다 — 캡처 이미지가 아니라 도형이라 확대해도 깨지지 않고 고칠 수 있다.
  ```yaml
  - layout: free-title
    title: [...]
    source: {file: 원고.pptx, slide: 2, from: 3.2}
  ```
- **가져오면서 바꾸는 것은 스타일뿐이다.** 글꼴을 Pretendard로, 원고의 브랜드 파랑
  (006EFF·0066FF·0070C0·0081FF)을 Primary로 바꾸고, 비율을 유지한 채 가이드라인 안쪽으로
  맞춰 넣는다. **빨강 화살표·주황 강조처럼 의미를 담은 색은 건드리지 않는다.**
- **좌표는 도형마다 직접 고쳐 쓴다.** 그룹 배율(`chExt`)에 맡기면 파워포인트와 LibreOffice가
  글자 크기를 서로 다르게 처리해 렌더 확인이 믿을 수 없게 된다. 글자 크기도 같은 비율로 줄인다.
- **검사기가 이식분을 가려낸다.** 원고 도식의 색은 팔레트 밖이지만 그것이 원고의 내용이므로
  팔레트 검사에서 빼고, 대신 "원고에서 이식한 도식 N개 (…장)"를 알려 준다.
- **`meta.body_only`** — 표지·목차·간지·뒷표지 없이 본문만 뽑는다. 기존 제안서에 끼워 넣을 때 쓴다.
  섹션 라벨은 `sections[].label`로 원고 표기를 그대로 쓸 수 있다.
- yaml 안의 원고·그림 경로를 **deck.yaml 파일 기준**으로 푼다 (어디서 실행하든 같은 파일).

### yaml 키 변경

- 비교 장표: `headers` + `panels` → **`panels` 안에 `header`를 넣는다.**
  ```yaml
  # v1.0
  headers: [A안, B안]
  panels: [[항목1, 항목2], [항목1, 항목2]]
  # v1.1
  panels:
    - {header: A안, summary: 왼쪽 요약}
    - {header: B안, summary: 오른쪽 요약}
  rows: [[{title: ..., body: [...]}, {title: ..., body: [...]}]]
  ```
- `focus-3`의 `panel: {title, headline, body}` → `panel_head` · `big_title` · `panel_body`로 펼쳐졌다.
- `kpi-3`의 `panel: {title, rows, caption}` → `panel_head` · `rows` · `caption`으로 펼쳐졌다.
- `chart-bar`의 `summaries` → `right` (좌우 날개 구조로 바뀌었다).
- 섹션에 `subs`가 추가됐다 (하위 섹션 간지).
