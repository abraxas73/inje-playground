# 이노그리드 표준 PPT 자동 생성 (템플릿 v1.0 최신본 · 2026-09 · 디자인가이드 병합본 · 106장)

원고를 넣으면 이노그리드 디자인 규칙을 지킨 PPT가 나오는 도구다.

**사용자는 디자인 규칙을 몰라도 된다.** 규칙은 전부 템플릿과 코드에 박혀 있고,
어기면 예외가 나거나 검사기가 잡는다. 색·폰트·좌표·여백을 만질 수단 자체가 없다.

**당신이 할 일은 하나 — 원고를 읽고 각 덩어리에 맞는 장표를 고르는 것.**

Windows · macOS · Linux 모두에서 돈다.

---

## 이 폴더에서 처음 시작한다면

사용자가 원고를 주면서 "PPT로 만들어 줘"라고 하면, 이 순서로 움직인다.

```
1. .venv 가 없으면 → python3 setup.py   (Windows는 python setup.py)
2. 원고를 읽고 deck.yaml 을 쓴다        ← §2가 이 판단의 전부다
3. build → check → render → 이미지를 직접 본다   (§1)
4. 넘치거나 어색하면 deck.yaml 을 고쳐 2번부터 다시
```

디자인 가이드·템플릿·폰트·표준 프롬프트는 전부 `template/` 안에 있다. 따로 받을 것이 없다.

사용자가 `template/INNOGRID_PPT_Prompt.txt`의 사내 표준 프롬프트로 요청하면, 그 **절대 준수 규칙 7항 ·
필수 준수 사항 10항 · PPT 원고 9항**은 전부 이 도구의 기본 동작이다 — 와이드스크린, Pretendard 전용,
템플릿 색, 여백·위치·가이드라인 준수, **슬라이드 노트 준수사항 전부 적용**, 목차·타이틀 자동 생성,
타이틀 문장형(`~합니다.`), 불릿 요약·과도한 요약 금지·`~니다` 지양, 본문이 많으면 **8pt까지 축소**,
하위 목차가 있으면 **`01. 섹션명 : 하위섹션명`**, 메세지형은 짧게, 박스는 텍스트 양에 따라 커지고
**형제는 가장 큰 박스 기준**, 원고 PPT의 표는 템플릿 표 스타일, 산출물에서 **템플릿 슬라이드 구역 제거**.
당신이 따로 할 것은 **장표 선택과 원고 요약**뿐이다.

사용자에게 디자인 규칙을 묻지 마라. 색·폰트·여백은 이미 정해져 있고
당신이 고를 수 있는 것은 **어떤 장표에 담을지**뿐이다.

## 0. 처음 한 번 (환경 준비)

### 0-1. 디자인 원본은 이미 들어 있다

```
template/INNOGRID_PPT_Template_v1_0_latest.pptx   디자인가이드 + 템플릿 병합본 (106장 · 2026-09-17 갱신 최신본). 수정 금지
template/INNOGRID_PPT_Prompt.txt                  사내 표준 프롬프트 (최신본)
template/사용서체.zip                              Pretendard 9종. setup.py가 설치한다
```

**이 파일들을 수정하면 규칙 보장이 깨진다.**

(다른 위치의 템플릿을 쓰려면 환경변수 `INNOGRID_PPT_TEMPLATE` 또는 `build.py --template <경로>`.
86장짜리 v1.1, 33장짜리 v1.0, 26·22장 이전 배포본은 번호·좌표가 전부 달라 쓸 수 없다.)

### 0-2. 파이썬이 없다면 설치한다

파이썬 **3.9 이상**이 필요하다. `python --version` 또는 `python3 --version`으로 확인한다.

| OS | 설치 |
|---|---|
| Windows | `winget install --id Python.Python.3.13 -e` |
| macOS | `brew install python@3.13` (Homebrew 없으면 https://brew.sh) |
| Linux (deb) | `sudo apt install python3 python3-venv` |
| Linux (rpm) | `sudo dnf install python3` |

### 0-3. 나머지는 스크립트가 한다

```
python setup.py            # Windows
python3 setup.py           # macOS · Linux
```

가상환경 생성 → 의존성 설치 → LibreOffice·poppler 점검 → Pretendard 설치 →
**예제 덱을 실제로 만들어 보고** 결과를 보고한다. 점검만 하려면 `--check`.

끝나면 앞으로 쓸 파이썬 경로를 출력한다. **이 문서에서 `PY`는 그 경로를 뜻한다.**

```
macOS · Linux :  .venv/bin/python
Windows       :  .venv\Scripts\python
```

## 1. 작업 절차

```bash
# 1) 원고를 deck.yaml로 옮긴다   ← 당신이 하는 유일한 판단 = 장표 고르기
# 2) 생성
PY build.py deck.yaml out.pptx

# 3) 규칙 검사 — 반드시 돌린다
PY check.py out.pptx

# 4) 눈으로 확인 — 반드시 한다
PY render.py out.pptx
#    .claude-workspace/ 에 만들어진 slide-1.jpg … 를 Read로 열어 직접 본다
```

임시 파일(pdf·jpg·중간 yaml)은 전부 `.claude-workspace/` 아래에 만든다.

**3·4단계를 건너뛰지 마라.** 특히 4단계 — 도형이 겹쳤거나 글이 어색한 것은
렌더해야만 드러난다. (상자 밖으로 넘치는 것은 빌드가 먼저 막는다. §5 참고)

빌드가 찍는 `[권고]`는 전부 읽는다. 상자를 늘렸다 · 8pt로 줄였다 · 마침표를 지웠다 · 하위 섹션 라벨이
없다 같은 것들이다 — 도구가 규칙대로 손을 봤다는 보고이자, 원고 정리가 더 필요하다는 신호다.

## 2. 장표 고르기 — 이것만 정확하면 된다

템플릿 최신본은 본문 장표를 **66종**(+ 카드 5·6단, flow-4 변형) 갖고 있다. 겁먹을 것 없다. 아래 3단계로 좁힌다.

### 2-1. 먼저 "무엇을 보여주는가"로 큰 갈래를 정한다

```
행·열이 있는 값의 나열            →  표      (§2-5)
비율·구성(전체 중 몫)             →  chart-donut   (항목 ≤5)
시계열·항목별 크기 비교           →  chart-bar · chart-notes  (항목 ≤5)
안건·항목의 짧은 목록 (표 아님)   →  agenda-5 (≤5행. 더 많으면 cards-8 또는 두 장)
한 문장으로 못 박을 메시지        →  message  (검정 배경 40pt 한 줄. 필수 아님)
그림·스크린샷이 주인공            →  image-*  (§2-4)
수치(KPI) 몇 개가 주인공          →  kpi-4-cards-3 · kpi-3-cards-3 · cards-3-kpi-4 · image-4-kpi* · panel-rows*
논리 관계가 있는 서술             →  §2-2
```

### 2-2. 항목들이 서로 어떤 관계인가

| 원고가 이런 모양이면 | 장표 |
|---|---|
| 서로 독립한 병렬 나열 | `card-4` `card-3` (5·6개면 `card-5` `card-6`) · 본문이 6개 이상으로 길면 `card-3-chips` |
| 한두 단어짜리 대등 개념 | `circle-4` `circle-3` (연결선형은 `-line`) |
| 결론 먼저, 그다음 근거 n개 | `lead-4` `lead-3` · 근거마다 키워드가 있으면 `lead-3-chips` |
| 3가지 축(헤더)마다 설명 | `columns-3-chips` · 축 × 관점 격자면 `columns-3x3` |
| 항목마다 "설명 → 그래서 결론" | `pill-4` `pill-3` (결론을 한 줄로 맺으면 `-msg`, 단서를 달면 `pill-3-note`, 결론+단서면 `pill-3-summary-note`) |
| 순서·단계·시간축이 의미를 가짐 | `steps-6` `steps-8` `steps-10` · `flow-4` `flow-6` `flow-8` · 일정 4단계 + 정리 3개면 `timeline-4-notes-3` |
| 항목이 6·8·10개인 나열 | `cards-6` `cards-8` `cards-10` (한 줄 결론) · `cards-8-note` `cards-10-note` (아래 단서) |
| 하나가 나머지를 지배 (중심 + 사방 4) | `radial-4` |
| 둘을 맞세워 비교 | `compare-rows` `compare-cards` `compare-vs` |
| 변화 전 → 후 (두 칸 + 부연) | `change-2-notes` `change-2-note` |
| 큰 주장 하나 + 그것을 받치는 것들 | `panel-cards-3` `panel-2-cards-3-note` `panel-cards-6` |
| 수치 패널 + 근거 카드 | `panel-rows` `panel-rows-note` |
| 같은 대상을 두 층위로 (현황 → 대응) | `stack-3` |
| 가운데 흐름을 좌우 요약이 감쌈 | `wing-rows` `wing-circle` `wing-message` |
| 왼쪽 개념 하나 + 오른쪽 세부 나열 | `split-3` |

### 2-3. 단 수는 이름의 일부다

`card-4`에 카드 3개를 주면 **예외가 난다.** 개수를 줄이거나 늘리는 건 **당신의 편집 판단**이지
도구가 대신 해줄 일이 아니다.

**카드형은 3단부터 6단까지 쓸 수 있다** (템플릿 노트 20·21: "카드는 3단부터 6단까지 활용가능").
`card-5` `card-6`은 가이드의 그리드로 다시 깔아 만든다. 어느 단이든 가이드라인을 가득 채우고 간격은 동일하다.

| 단 | 카드 폭 | 본문 한 줄 |
|---|---|---|
| 3단 | 8.74cm | 약 24자 |
| 4단 | 6.50cm | 약 17자 |
| 5단 | 5.17cm | 약 12자 |
| 6단 | 4.26cm | 약 10자 |

| 원고 항목 수 | 처리 |
|---|---|
| 2 | `compare-*` `change-2-*`로 대조하거나, 내용을 묶어 3개로 |
| 3~6 | `card-3` `card-4` `card-5` `card-6` |
| 4 | `flow-4` `timeline-4-notes-3` (단계·흐름일 때) |
| 6 | `cards-6` `steps-6` `flow-6` |
| 8 | `cards-8` `cards-8-note` `steps-8` `flow-8` |
| 10 | `cards-10` `cards-10-note` `steps-10` |
| 그 밖 | 묶어서 줄이거나 장을 분리 `(1/2) (2/2)` |

**칸이 많을수록 본문이 짧아야 한다.** 6단은 한 줄에 10자 남짓이다.

**애매하면 `card-*`를 골라라.** `circle-*`은 원 안이라 본문 칸이 가장 좁아
서술형 문장을 넣으면 반드시 넘친다 (노트 18: "본문이 많지 않을 때 위주로").

### 2-3-1. 타이틀 한 줄 + 부가 설명

원고에서 **설명이 타이틀 위에** 있는 구성(제안서에서 흔하다)은 템플릿 기준으로 뒤집는다 —
**타이틀이 위, 부가 설명이 아래**다 (템플릿 노트 8). 타이틀을 한 줄로 쓰고 `lead`를 준다.

```yaml
- layout: card-4
  title: 통합 이후 첫 전사 타운홀을 10월에 엽니다.   # 한 줄
  lead: 오전 타운홀과 오후 Culture Day를 하루로 묶어 운영합니다.
```

타이틀이 두 줄이면 `lead`와 겹치므로 `[권고]`가 뜬다. 둘 중 하나를 고른다.

### 2-4. 이미지형은 그림이 있을 때만

`image-3` `image-4`는 카드 아래, `image-3-top` `image-4-top`은 위쪽에 그림 자리가 있다.
`image-4-kpi` `image-4-kpi-msg`는 그림 4장 아래에 **수치(KPI) 4개**가 붙는다.

**원고에 그림이 있으면 반드시 가져다 쓴다** (템플릿 노트 17: "원본파일에 이미지가 있다면
원본파일에서 가져다 사용하시길 바랍니다. 임의 삭제 X"). `images`에 파일 경로를 주면
비율을 유지한 채 가운데를 잘라 넣고 모서리를 둥글린다.

```yaml
- layout: image-4
  images: [evidence/01.png, evidence/02.jpg, evidence/03.png, evidence/04.jpg]
  cards: [...]
```

원고가 PPT면 그림을 먼저 뽑는다.

```bash
PY -c "from innogrid_ppt.media import extract_images; \
       print(extract_images('원고.pptx', 'images/', slide_no=15))"
```

주지 않은 자리는 템플릿 그림이 그대로 남는다 — 비우면 디자인이 무너지기 때문이다.
그림이 아예 없는 원고라면 `card-*`를 쓴다.

### 2-5. 표

표는 **꼭 필요할 때만** 쓴다. 행·열이 있는 진짜 데이터(수치 비교표, 일정표, 지표표)만
`table*`로 만들고, "항목 / 영향 / 대응 / 담당"처럼 표로도 쓸 수 있는 서술은
`card-*` `lead-*` `pill-*` `compare-*`로 도식화한다. 본문의 1/4를 넘게 표를 쓰면 `[권고]`가 뜬다.

| 상황 | 장표 |
|---|---|
| 행이 많은 표 하나 | `table-full` (마무리 없음) |
| 표 + 아래 마무리 바 | `table` |
| 표를 읽은 결론이 "현행 → 개선" | `table-flow` |
| 설명을 먼저 하고 표로 뒷받침 | `table-lower` |
| 표 아래 관점 두 가지 | `table-notes` |
| 표 아래 단서·주석 한 덩어리 | `table-note` |

행 수는 자유다. **열 폭은 글자수가 정하고**(가장 긴 셀이 넓은 열을 갖는다), 긴 셀은 줄바꿈되며
**행 높이가 여백을 유지한 채 커진다** (템플릿 노트 85~87). 자리를 넘치면 7.5pt로 한 번 더 시도하고,
그래도 넘치면 행을 나눠 두 장으로 한다. 원고 PPT의 표는 **어떤 서식이었든 템플릿 표 스타일로** 다시 그린다.

### 2-6. 템플릿으로 표현하기 어려운 내용 — 원고 도식을 그대로 이식한다

프롬프트 "원고가 PPT 파일일 경우" — 템플릿 레이아웃으로 안 되는 원고는
**원고의 레이아웃을 유지하되 디자인 스타일만 맞춘다.** 노드 수십 개짜리 아키텍처 구성도를
card·flow로 다시 그리면 반드시 내용이 깎인다. 그럴 땐 `free-title`에 `source`를 준다.

```yaml
- layout: free-title
  title: ["원고 타이틀을 문장형으로 고쳐", "두 줄로 적습니다."]
  source:
    file: 원고.pptx      # deck.yaml 기준 상대경로
    slide: 1            # 원고 몇 번째 장인가 (1부터)
    from: 3.2           # 이 y(cm) 위쪽은 가져오지 않는다 (원고의 라벨·타이틀)
```

**캡처 이미지가 아니라 도형을 그대로 가져온다** — 확대해도 깨지지 않고 받는 쪽에서 고칠 수 있다.
가져오면서 바뀌는 것은 스타일뿐이다: 글꼴을 Pretendard로, 원고의 브랜드 파랑을 Primary로 바꾸고,
비율을 유지한 채 가이드라인(좌우 1.35 / 아래 15.35) 안쪽으로 맞춰 넣는다. 빨강 화살표·주황 강조처럼
**의미를 담은 색은 건드리지 않는다.** 검사기는 이식분을 팔레트 검사에서 빼고 개수만 알려 준다.

`from`은 원고를 열어 라벨·타이틀이 끝나는 y를 재서 준다. 필요하면 `to`(아래 잘라내기),
`area: [x, y, 폭, 높이]`(넣을 자리 직접 지정), `align: center`(세로 가운데), `recolor: false`도 쓴다.

도식만 남기고 끝내지 말 것 — **같은 내용을 템플릿 장표로 한 번 더 요약해 붙인다.**
원고 구성도 한 장 + 요약 한 장이 기본 짝이다.

**원고가 PPT일 때 지킬 것** (프롬프트): 장표 수와 순서는 원고 그대로 (내용이 많다고 임의로 합치거나
나누지 않는다) · 원고에서 굵게·크게 강조한 부분은 `[[강조]]`로 살린다 · 원고 레이아웃과 가장 비슷한
템플릿 장표를 고르고, 없으면 컴포넌트를 조합한 `free-title` + `source`로 간다.

### 2-6-1. 본문만 뽑기

기존 제안서에 끼워 넣을 때는 표지·목차·간지·뒷표지 없이 본문만 만든다.

```yaml
meta:
  body_only: true
```

### 원고를 옮길 때 지킬 것 — 편집 규칙 (프롬프트 필수 준수 사항)

**타이틀 — 두 줄이 이어져 한 문장이 되고 "~합니다."로 끝난다.**
1행은 2행을 꾸미는 수식구, 2행은 주어와 서술어다. 2행이 파랑이 되므로 핵심 명사를 2행에 둔다.
```
✗ ["세 가지 성공 조건", "기술보다 조직이 먼저 갖춰야 할 것"]       ← 명사구 두 개를 나열
✓ ["기술보다 조직이 갖춰야 할", "세 가지 성공 조건은 다음과 같습니다."]
✗ ["단계적 전환으로 위험을 낮춘다", "한 번에 옮기지 않고 …"]           ← "~한다"체
✓ ["한 번에 옮기지 않고 워크로드 성격별로 나누는", "단계적 전환으로 위험을 낮춥니다."]
```
1행이 "~다." "~것"으로 끊기거나 2행이 "~합니다."로 끝나지 않으면 빌드 시 `[권고]`가 뜬다.
**원고에 타이틀이 명확하면 내용을 바꾸지 않는다** — 문장형으로 어미만 다듬는다 (노트 7).

**불릿 — 원고 문장을 살린 한 줄이되, "~니다"로 맺지 않고 마침표를 찍지 않는다.**

yaml에서 **리스트로 주면 블릿형**(마침표 없음), **문자열 하나로 주면 서술형**(마침표 유지)이다 —
템플릿 노트 14~16 "블릿형 본문은 마침표를 사용하지 않습니다. (서술형은 사용)".
```yaml
body: [표준 이미지가 없어 설정이 갈리는 것, 배포가 수작업이라 실수가 반복됨]   # 블릿형
body: 표준 이미지가 없어 환경마다 설정이 갈립니다.                              # 서술형
```

**리스트의 원소 하나가 곧 문단 하나다.** 노트 28~81 "각 본문의 내용이 길어질 경우 글자가 아닌
**문단 단위로 줄갈이**" — 긴 서술을 글자 수로 잘라 두 원소로 쪼개지 말고, 문장이 자연스럽게 끊기는
자리에서 문단을 나눈다. 원고가 4문장 이상의 서술형이면 블릿으로 요약하되(프롬프트), 과도한 요약은 금지다 —
단어 나열로 줄이지 마라. 모든 줄이 "~합니다"로 끝나면 어색하므로 명사형·"~하는 것"·"~할 것"·"~함"으로 맺는다.
**박스 안 불릿에는 마침표를 붙이지 않는다.** 붙여 두면 도구가 떼고 `[권고]`를 낸다.
```
✗ "고정비 72%"                                       ← 과요약
✗ "장애 시간을 최소화하는 것이 첫 번째 목표입니다"      ← "~니다" 종결
✗ "장애 시간을 최소화하는 것이 첫 번째 목표."           ← 마침표
✓ "장애 시간을 최소화하는 것이 첫 번째 목표"
✓ "배포 절차가 수작업이라 사람 실수가 반복됨"
```

**불릿은 3개, 많아도 4개.** 템플릿 노트가 "박스의 본문은 3개까지"라 하므로 5개 이상이면
`[권고]` — 문단을 합치거나 장을 나눈다. 예외는 마무리 문구·요약 문장(`closing`·`summary`·
`summaries`) — 이것은 문장이므로 "~합니다."로 끝내고 마침표를 붙인다.

**하단 마무리 문구는 반드시 채우고, 두 줄을 넘기지 않는다.** 슬롯이 있는 장표에서 `closing`·`summary`는
**필수**이고 비어 있으면 빌드가 실패한다. 원고에 마무리 문장이 없으면 **그 장표의 내용을 분석해
결론을 한두 줄로 만들어 넣는다.** 메세지형 컴포넌트는 두 줄까지다 (가이드 12·13 "긴 서술형 지양") —
세 줄이면 빌드가 막는다. 한 줄이면 박스가 한 줄 높이로, 두 줄이면 두 줄 높이로 **바닥을 고정한 채**
저절로 맞춰진다 (노트 "하단 텍스트 박스는 하단고정").

그 밖에:
- **원고에 목차가 없으면** 내용을 분석해 섹션을 만든다. **있으면 변경 금지.**
- **하위 목차가 있으면** `sections[].subs`에 적고 장표마다 `sub:`를 준다 → 라벨이 `01. 섹션명 : 하위섹션명`이 된다.
  빠뜨리면 `[권고]`가 뜬다.
- **원고에 장표 제목이 없으면** 그 덩어리를 요약해 위 규칙대로 두 줄 문장을 만든다.
- **본문이 넘치면 도구가 ① 상자를 아래로 늘리고(형제 카드도 같은 높이로) ② 그래도 안 되면 8pt로 줄인다.**
  둘 다 `[권고]`로 보고한다. 8pt까지 갔다는 것은 글이 많다는 뜻이니 가능하면 원고를 다듬는다. 8pt 밑으로는 절대 안 간다.
- `[[ ]]`로 감싼 부분만 강조색이 된다. 원고 PPT에서 굵게·크게 강조한 부분은 이것으로 살린다.
  **어두운 바 위 흰 글자에서는 무시된다** — 도구가 템플릿을 보고 자동 판정한다.
- **칩은 글자수에 맞춰 가로 폭이 자동 조정된다** (노트 9). 칩 폭의 합이 카드를 넘으면 오버플로 예외가 난다 —
  키워드를 짧게 하거나 개수를 줄인다. 항목 Pill·패널 헤더 같은 **바 타이틀은 콘텐츠 폭을 따르므로 줄어들지 않는다.**
- **차트는 데이터만 바꾼다.** 항목은 **5개까지** (노트 82~84). 비율 차트는 합이 100이 되게 준다.
- **채울 수 없는 것만 비운다.** `keywords`·`caption`·수치 행·화살표 설명·`tag`는 원고에 없으면
  도형째 지워진다. 마무리 문구는 여기 해당하지 않는다 — 만들어 넣는다.
- **표지 부서명**은 원고에서 파악되면 `meta.dept`에 넣고, 파악이 힘들면 비운다 → "부서명"으로 표기된다 (노트 22).

## 5. 막혔을 때

### `템플릿이 106장이어야 하는데 …장이다`

`template/INNOGRID_PPT_Template_v1_0_latest.pptx` 가 지워졌거나 이전 배포본이 들어 있다.
압축본에서 다시 꺼내거나 디자인센터에 사내 배포본(2026-09 최신본, 106장)을 요청한다.

### `'…' 슬롯이 넘친다 — N줄이 필요한데 상자는 M줄이다`

**도구가 먼저 상자를 키우고, 그 다음 8pt로 줄여 본다** (템플릿 노트 "본문이 길어지면 박스도 아래로 같이
커집니다" · 프롬프트 "8pt까지 줄여도 됨"). 이 메시지가 뜬 것은 **둘 다 해도 자리가 없다는 뜻**이다.

**이 순서대로.**

1. **글을 줄인다** — 불릿을 합치거나 수식어를 뺀다 (단, 과요약 금지)
2. **항목 수를 줄인다** — 4단 → 3단
3. **더 넓은 장표로 교체** — `circle` → `card`, `steps-10` → `steps-6`, 카드형 → `table`
4. **장을 분리** — 제목에 `(1/2) (2/2)`를 붙여 두 장으로
5. 표만 예외 — 자리를 넘치면 7.5pt까지 자동으로 시도한다

칸이 남으면 그냥 비워 둔다. 억지로 채우지 않는다.

> 이 판정은 **상자 실측값**에서 나온다 (`capacity.py`). 템플릿을 바꿨다면
> `python tools/measure.py`로 다시 재야 한다.

### `마무리 문구가 N줄이다 — 메세지형 컴포넌트는 2줄까지다`

문장을 줄인다. 마무리 문구는 결론 한 줄이 원칙이다 (가이드 13 "핵심 정보를 간결하게").

### `마무리 문구가 2줄인데 박스를 위로 키울 자리가 없다`

본문 카드가 하단 박스 바로 위까지 내려와 있는 장표다. 마무리를 한 줄로 줄이거나 본문을 덜어낸다.

### `'card-4'는 항목 4개 고정인데 3개가 왔다`

`card-3`를 쓴다. 4단에서 카드를 하나 지우는 방식은 안 된다 — 도형 그룹에 배율이
걸려 있어 나머지 카드가 찌그러진다.

### `… 마무리 문구(closing)가 필수다`

장표 내용을 읽고 결론을 한두 줄로 써서 `closing`에 넣는다. 카드들이 공통으로 말하는 것,
또는 "그래서 무엇을 해야 하는가"가 마무리 문구다.

### `키워드 칩 폭 합계가 …cm를 넘는다`

칩 폭은 단어 길이에 맞춰 자동으로 늘어난다. 합이 카드 안쪽 폭을 넘으면 예외다.
키워드를 짧게 바꾸거나 개수를 줄인다.

### `표가 …cm 로 자리를 넘친다`

행을 나누어 두 장으로 하거나 셀 글을 줄인다. 열이 많으면 `table-full`(표 전용 장표)을 쓴다.

### `'…'는 이전 템플릿 이름이다`

v1.1(86장)·v1.0(33장) 시절 yaml이다. 오류 메시지가 대응 이름을 알려준다. `CHANGELOG.md`에 전체 표가 있다.

### `check.py`가 위반을 보고한다

최신본 본문 장표는 팔레트·폰트·줄간격 위반이 **하나도 없다.**
그러므로 **위반이 나오면 진짜 문제다.** 특히:

- *팔레트 밖 색* → 코드가 색을 새로 쓰고 있다
- *템플릿 잔여 문구* (`내용이 들어갑니다`, `키워드 1`, `설명이 들어갑니다` 등) → 슬롯을 안 채웠다
- *제품 지정색* → 제품 장표가 아닌 곳에서 제품색을 썼다

단 하나, **알려진 템플릿 원본 결함**이 있다: AI큐브잇 주요 기능 장표(원본 103)에
`KoPub돋움체 Medium` 런이 두 군데 남아 있다. 그 제품 장표를 쓰면 따라오므로
디자인센터에 수정을 요청할 것.

### `render.py`가 실패한다 / 폰트가 이상하다

LibreOffice(`soffice`)와 poppler(`pdftoppm`)가 필요하다. `PY setup.py`가 설치를
시도하고, 실패하면 OS별 설치 명령을 알려준다.

폰트는 **Pretendard 9종을 시스템에 설치**해야 한다. LibreOffice가 pptx 안의 임베드
폰트를 못 읽어서 렌더는 시스템 폰트로 그려진다. 없으면 줄바꿈이 달라져 판정이 틀린다.
Windows는 자동 설치가 안 되므로 `setup.py`가 풀어 준 폴더에서 `.otf` 전체 선택 →
오른쪽 클릭 → 설치를 한 번 해야 한다.

산출물 pptx 자체는 폰트가 임베드되므로, 렌더 확인을 못 해도 받는 쪽에서는 정상으로 보인다.
LibreOffice 렌더에서 작은 칩(7pt 꼬리표)이 좁게 보이는 것은 렌더러 문제다 — PowerPoint에서는 정상이다.

## 6. 새 장표를 지원해야 한다면

`TEMPLATE_ANALYSIS.md`를 먼저 읽어라. 특히 §3-1(노트 → 규칙 대응표)과 §4(자동화 함정)를 건너뛰면 반드시 깨진다.

장표 하나를 붙이는 데 **빌더를 새로 짜지 않는다.** `tokens.LAYOUTS`에 스펙 한 덩어리를 적으면 끝이다.

```python
"card-4": _L(28, arity=4, desc="카드 4장 + 마무리 바",
    groups=[_G("cards", 4, num=5.05, title=5.92, body=7.80)],
    closing=_C(12.56, "bar16"), closing_required=True),
```

핵심 세 가지:

1. **도형을 새로 그리지 마라.** 원본 슬라이드를 복제하고 텍스트만 갈아끼운다.
   그래서 브랜드 위반이 발생할 수 없다.
2. **슬롯은 좌표로 찾는다.** 도형 이름은 못 믿는다 — `"Text 3"`이 슬라이드마다 다른
   역할이고 중복도 된다. y 좌표가 곧 역할이고, 같은 밴드 안에서 x 순서가 인덱스다.
3. **좌표는 절대(화면) 좌표다.** `geom.py`가 그룹 변환(`chOff`/`chExt`)을 풀어 주므로
   자로 잰 값을 그대로 적으면 된다.

좌표를 재려면 아래 한 줄로 그 장표의 글상자를 전부 뽑아 본다.

```bash
PY -c "from pptx import Presentation; from innogrid_ppt.geom import walk_abs; \
p=Presentation('template/INNOGRID_PPT_Template_v1_0_latest.pptx'); \
[print(round(n.y,2), round(n.x,2), round(n.w,2), round(n.h,2), n.shape.text_frame.text[:30]) \
 for n in sorted(walk_abs(p.slides[27].shapes), key=lambda n:(n.y,n.x)) if n.shape.has_text_frame]"
```

새 스펙을 적었으면 `python tools/measure.py`로 용량표를 다시 만들고, `tools/make_sample.py`의
`SECTIONS`에 이름을 넣어 예제도 갱신한다.
